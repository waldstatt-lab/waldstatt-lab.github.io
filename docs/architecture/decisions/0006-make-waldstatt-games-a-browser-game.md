# 0006 — Make Waldstatt Games a browser game that gates its content

> Superseded by [ADR 0010](0010-move-waldstatt-games-into-its-own-repository.md):
> Waldstatt Games moved to its own repository,
> [waldstatt-lab/waldstatt](https://github.com/waldstatt-lab/waldstatt), where this decision
> lives on. The record stays for its rationale; its links point to this
> repository as it was before the move.

**Amended by [ADR 0007](0007-save-waldstatt-games-in-indexeddb.md):** the
game state moved from `localStorage` to an IndexedDB database of its own,
`waldstatt-games`. The rules below for storage (untrusted input, a reset that
touches only this variant's data) apply to it unchanged.

## Context

The [pitch](https://github.com/waldstatt-lab/waldstatt-lab.github.io/blob/04ce560ec337419cc36983e4c10d08c2816cbf51/docs/pitches/waldstatt-games/pitch--aufbauspiel-im-wald.md) turns the
Waldstatt Games variant into a building game: the home page is an endless forest,
and visitors unlock the site's content by felling trees and building. The studio
chose a strict gate: content is reached only through play, the variant's about and
game pages are removed, and there is no text fallback. This breaks rules that
[ADR 0001](0001-build-a-static-site-with-astro-and-daisyui.md) and
[ADR 0004](0004-allow-optional-client-side-scripts-in-a-variant.md) set for every
variant:

- every page's content and links work without JavaScript (0004);
- scripts use no storage and load no third-party code (0004);
- no client-side rendering library; November Games used native Canvas 2D for a
  single bounded scene ([ADR 0005](0005-enhance-november-games-with-local-interactions.md)).

A game whose state must survive reloads needs storage, and an endless,
changing forest with thousands of sprites is beyond a small hand-written canvas
script.

Alternatives considered for the content gate:

- **A playable home page beside plain archive pages.** Keeps 0004 intact for the
  content, but makes the game optional decoration. The studio rejected it.
- **Play only, with a `<noscript>` summary.** Rejected for the same reason.
- **Play only, with no fallback.** Chosen.

Alternatives considered for rendering:

- **Native Canvas 2D.** No dependency, but batching, culling and texture
  management for an endless forest would have to be written by hand.
- **PixiJS (WebGL 2D).** GPU sprite batching, culling and textures; one npm
  dependency of a few hundred kilobytes on this variant's page only.
- **Babylon.js.** A 3D engine for a 2D map.
- **Bevy compiled to WebAssembly**, the games' engine. Megabytes of download and
  a slow start for a home page, a Rust toolchain in CI, and text drawn on a canvas
  instead of HTML.

## Decision

For the Waldstatt Games variant only:

- Its home page is a game that needs JavaScript and WebGL. Its content, the
  studio texts, the shared game texts and the play and source links, is revealed
  only through play. `/waldstatt-games/ueber-uns/` and
  `/waldstatt-games/spiele/<spiel>/` do not exist. Without JavaScript or WebGL,
  the page shows a still picture, the name and a note, with no content or links.
- The content stays real HTML. Astro renders the texts at build time into inert
  `<template>` elements, and the script clones them into HTML panels over the
  map; it sets no HTML from strings.
- The map is rendered with PixiJS 8, bundled from npm through Astro and served
  from the site. The panels, menus and toolbox are HTML styled by the variant's
  theme.
- The game state is one versioned JSON document in `localStorage` under keys
  starting with `waldstatt-games/`. It is validated as untrusted input, and
  resetting removes only those keys.
- The waters on the map are real: `tools/waters.mjs` in the variant's folder
  generates them from swisstopo and BAFU data while developing, as November
  Games' panorama tool does, and the site never contacts swisstopo.
- A web manifest and a service worker make the variant installable and
  playable offline. Both are generated by endpoints in
  `src/pages/waldstatt-games/`, and the worker's scope is
  `/waldstatt-games/` under the base path. It caches only that build's files.

The other rules of ADR 0004 still apply: no network requests other than for the
site's own files, keys handled only inside focused widgets or the focused map,
and `prefers-reduced-motion` honoured. Every other variant and the overview stay
under ADRs 0001 and 0004 unchanged.


## Consequences

- The variant can be a real game, and the name's story, people clearing a forest,
  becomes something visitors do.
- Search engines, visitors without JavaScript or WebGL, and most screen-reader
  users cannot reach the variant's content. This is accepted for a name
  experiment. It must be revisited if Waldstatt Games becomes the studio's site.
- The variant's route table differs from every other variant's, and the
  architecture documentation has to say so.
- One dependency, PixiJS, enters `package.json` and needs updates like any
  other. Its bundle is loaded only on this variant's page.
- The organization's Pages sites share an origin and thus `localStorage`. The
  key prefix, and a worker scope no wider than the variant's path, keep the
  variant from touching the games' saves or other pages.
- A service worker can serve a stale build. Cache names follow the build, and the
  page is fetched network-first.

## The tell

- `rg -n "localStorage|sessionStorage|indexedDB|serviceWorker" src` finds
  matches only in `src/variants/waldstatt-games/` and
  `src/variants/november-games/`; every Waldstatt key starts with
  `waldstatt-games/`, and its only database is `waldstatt-games`.
- `rg -n "from \"pixi.js\"" src` finds imports only in
  `src/variants/waldstatt-games/`.
- `ls src/pages/waldstatt-games/` shows `index.astro` and the manifest and
  worker endpoints, with no `ueber-uns.astro` and no `spiele/`.
- `rg -n "localStorage.clear" src` finds nothing.

A search cannot show that the worker's scope stays narrow or that a reset leaves
the games' saves alone. Check both by hand in the browser's application panel
after playing a game and resetting the forest.
